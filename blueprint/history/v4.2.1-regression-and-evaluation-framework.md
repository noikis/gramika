## Goal

Establish an offline baseline for the existing deterministic text diff before changing behavior. Extend the existing server `node:test` suite using one synthetic corpus for automated assertions and a small file-reporting command. Separate structural correctness, current behavior, exploratory presentation expectations and performance evidence.

Authority: build-plan V4.2 delivery contract; improvement specification Step 1 (§4), cross-cutting requirements (§3) and evaluation guidance (§12). Only V4.2.1 is proposed here.

## In scope

- Approximately 30–50 committed synthetic cases with stable IDs, exact original/corrected strings, categories, expected-behavior descriptions, confirmed/exploratory status and optional mode notes. Include every §4.3 starting example and §4.2 category.
- Shared fixture evaluation and stronger invariants, retaining the existing targeted and seeded generated regressions.
- Behavioral assertions supporting exact and intentionally flexible expectations, separated from future grouping goals.
- Presentation integration tests of current rendering: whitespace, empty sides, context versus highlights, multiple spans, deletions and punctuation. Characterize limitations without implementing Step 2.
- Performance measurements for 100, 400, 1,000 and 5,000 UTF-16 code units, including repeated words and substantial rewrites.
- Saved JSON/Markdown baseline and comparison reports in unique ignored local run directories, with focused tests for reporting and failure handling.

## Out of scope

- Production diff, tokenization, movement, grouping, spans, public schemas, prompts or UI behavior changes.
- V4.2.2–V4.2.5 implementation; spec Steps 6–7, selective semantic grouping and LLM-assisted grouping.
- New frameworks, dependencies, databases, CI workflows, application servers or browser harnesses.
- Real OpenRouter/model calls or model benchmark entry points, including preview mode.
- SSH, Playwright MCP, commits, merges, pushes or deployment without separate authorization.
