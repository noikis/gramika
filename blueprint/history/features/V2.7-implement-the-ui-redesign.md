## Goal

Apply the approved Figma Make visual direction to the working application,
with warm light mode and Charcoal & jade dark mode, while preserving correction,
inspection, explanation, clipboard and history functionality. Make the interface
comfortable on phones without importing the prototype's simulated behavior.

## In scope

- Shared semantic theme tokens, typography, cards, buttons, fields and feedback.
  System appearance is the default, with accessible System/Light/Dark controls.
  An override lasts for the current mounted app session; reloading returns to
  System. While System is selected, follow live OS changes. No persistence added.
- Centered, stacked input/result workspace and responsive navigation; clear
  mobile theme controls and comfortable spacing. English interface remains.
- Segmented two-mode selector using the existing labels and behaviors for now.
  Keep the current default; final naming is deferred, not new modes.
- Character count using the existing Unicode code-point validation semantics and
  shared MAX_INPUT_CHARACTERS limit, including over-limit feedback. Do not use
  the export's 2,000-character cap, truncate input or switch to word count.
- New correction reachable from either screen: return to the editor, clear the
  current input, results, selected-result/inspection state, errors and request
  association, preserve current correction mode and theme, and focus Original.
  It performs no API call and deletes no saved records. Disable it while a
  correction, second opinion, clipboard read or clipboard write is pending;
  invalidate old workspace associations so later requests cannot reuse them.
- Ctrl+Enter submits the normal Gemma correction from the input, through the
  existing validation/availability/pending guards. Support Cmd+Enter equivalently.
  Ignore IME composition. Never trigger another opinion or submit from a sheet.
- Labeled Paste near the input heading; desktop Copy near the result controls;
  prominent fixed mobile Copy for the active result. These positions are initial
  implementation choices to review, not immutable design decisions. Use 48px
  primary action heights and at least 44px effective secondary touch targets.
- Keep Text/Changes on editor and history results, Changes as the existing
  default, clean selectable text, and all real diff/inspector/explanation states.
- Preserve explicit Gemini second opinion, higher-cost messaging, model identity,
  retained results, independent view/selection state and safe failure handling.
- Restyle history while retaining search, model/result filters, From/To dates,
  existing local-date boundaries, sorting, pagination, reset, expansion and
  soft deletion with confirmation. Keep originals and all actual request results.
- Replace expanded request-details disclosure with an animated right side sheet
  on desktop and bottom sheet on mobile, using a tall, scrollable sheet for long
  details without requiring drag-to-expand. Keep existing summary metrics visible.
  Details belong to a specific history request, including failed/pending requests;
  no new editor metrics API or fabricated editor details.
- Request details action belongs near request Copy; Delete remains an entry-level
  action because it deletes the whole correction, not an individual request.
- Preserve kopeck conversion, USD fallback and explicit unavailable metrics.
  Restyle Sonner and all existing inline/loading/error/empty feedback for themes.
- Update only directly conflicting visual guidance in coding standards and the
  prototype README to point to docs/DESIGN.md, without rewriting product policy.
