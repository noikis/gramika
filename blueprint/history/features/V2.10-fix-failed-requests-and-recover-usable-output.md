## Goal

Display complete valid corrections normally, including Gemini second opinions,
even when the provider ignored the disabled-reasoning setting. Per the user's
2026-10-22 clarification, that setting violation is a logging-only detail.

## In scope

- Validate HTTP 200, one choice, stop finish reason, assistant content as nonblank
  text, no refusal or upstream error. Never show internal reasoning as output.
- Accept complete output as an ordinary HTTP 200 correction, persist succeeded
  and correctedText with reported usage/costs, and keep standard Copy, diff,
  second-opinion switching and Strict explanation eligibility.
- Log REASONING_NOT_DISABLED once using only request ID, model ID and operation.
  No UI warning, failure/retry state, reasoning text or personal text in logs.
- Retain disabled reasoning in request parameters. Preserve true failures for
  missing/malformed/truncated/refused output, upstream errors and timeouts.
- Keep original and earlier results on a genuine failure. Existing history
  search and result/model filters classify new valid outputs as normal successes.
- Historical rejected output was never saved and cannot be recovered locally.

## Out of scope

Paid requests, automatic retries, benchmark entry point/preview, reasoning
storage/rendering, migration, new recovery fields or public warning API,
cache/PWA work, SSH, commit and merge. Explanation-generation reasoning policy
is unchanged. Manual benchmark behavior remains unchanged.
