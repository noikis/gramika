# Feature: Browser persistence

**From build-plan:** feature V2.11b
**Build attempt:** 1
**Branch:** feature/browser-persistence
**Status:** verified

## Goal
Restore the current correction workspace on this device, using native localStorage and existing React state. Plan approved in chat on 2026-10-22. Keep implementation small; no React Query or new dependencies.

## In scope
- One versioned snapshot: exact untrimmed draft, current Gemma/Gemini results and identifiers, active result, mode, per-result Text/Changes view, theme and an interrupted-request marker.
- Restore automatically with Workspace restored notification. Retain until New correction or explicit clear; no expiry. New correction keeps preferences.
- Clear local data immediately, without confirmation, resetting workspace, mode and theme but keeping server history. Clear only this feature's stored workspace/preferences, not unrelated browser data or existing exchange-rate reuse.
- An interrupted request restores prior results and offers Check history, without resubmission. Check history navigates to the existing history screen; no automated reconciliation or recovery machinery.
- Deleting the associated history entry in this app clears its local results, retaining the original draft. No cross-device deletion synchronization.
- Tabs keep independent in-memory edits. Latest saved workspace is restored on next reopening. No cross-tab synchronization, locks or conflict handling.
- Corrupt/unsupported stored data and storage read/write/remove failures must not crash the editor or lose the active editing session. Report failures honestly. Local contents are validated before rendering and are never trusted to bypass server validation.

## Out of scope
PWA installability, service workers, offline loading, local history/explanation database, automatic request replay, multi-tab synchronization, dependencies and backend/API changes.
