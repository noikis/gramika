## Goal

Make Gemma the ordinary correction and Gemini an explicit second opinion,
retaining both results with one consistent result switcher on desktop and phone.

## Design reference

- `prototypes/another-opinion.html` and `prototypes/theme.css`, approved in chat
  on 2026-10-21 after the two-column refinement and conditional-arrow changes.
- Keep the existing blue-black/emerald palette, local Roboto and English UI.
  Theme tokens are already ported into `apps/web/src/index.css`; reuse them.
- Desktop has two columns: Original and one active Result. Mobile stacks them.
- Center Result and the model name above the result. No arrows until a successful
  Gemini result exists. With both results, Gemma shows only a right arrow and
  Gemini only a left arrow. Reserve both arrow slots so the title does not move.
- Swipe across the heading to switch models; leave text selection and vertical
  scrolling in the editor intact. Provide labeled keyboard-operable arrow buttons.
- One compact inspector beneath the active result shows model, Previous/Next,
  count and Original/Corrected passages. No explanation request is implied.
  Correction navigation shows only available directions: none for one change,
  Next at the start, Previous at the end and both between. Hide the count for
  a single change too. Apply the same principle to shared history result views.

## In scope

- Remove model selection and preference-saving controls from the correction UI.
  Correct always submits `DEFAULT_MODEL_ID` from the shared model registry.
  Existing saved preferences do not redirect this action to Gemini.
- Preserve Strict as the initial mode and the existing Gentle rewrite choice.
- After a successful Gemma result, offer Another opinion with Gemini 3.1 Flash
  Lite and Higher cost identified before submission. Use the exact original and
  mode of that Gemma result, with its existing correction ID.
  Desktop places this action above the result, alongside Mode above Original
  (user revision on 2026-10-21). Mobile retains the action beneath the result.
  The desktop control has a Second opinion label and matches Mode's width and
  height; its button shows Gemini 3.1 Flash Lite at left and Higher cost at right,
  without repeating Another opinion below the Second opinion label.
- Retain the Gemma result while Gemini is pending or fails. Show request-specific
  loading/failure feedback with explicit manual retry. Never invent a Gemini
  result or allow navigation to a pending/failed result.
- On Gemini success, retain both results and show Gemini. Switching between
  results makes no request and preserves each result's view, selected correction
  and internal editor scroll position. Copy always uses the active clean output.
- Prevent duplicate concurrent submissions. Keep original input on all failures.
  Editing the original invalidates the visible result pair and prevents stale
  responses from becoming the current result or association.
- If the selected mode differs from the displayed Gemma result, require Correct
  for that mode before Another opinion; never silently compare different modes.
- A new successful Gemma correction replaces the current workspace pair and
  resets its inspector/view state. Retain the previous pair during the request
  and on failure when its original still matches; persisted attempts remain in
  history. Repeated requests reuse the existing unchanged-original association.
- History continues showing only persisted attempts actually made, including
  failures and successful Gemma/Gemini attempts in their existing grouped entry.
  Do not add an Another opinion control or a placeholder Gemini result to history.
- Preserve configuration retry, validation, empty, unchanged, clipboard failure,
  unavailable-server and model-response error behavior. Keep expected API errors
  distinct from malformed/unexpected responses in request handling.

UUID `correctionId`, and `mode`. `CorrectionSuccess` identifies original, mode,
model, correction and request IDs with clean output. Validate response identity
before using it. Use the existing failure shape and public messages.

Gemma is `google/gemma-4-26b-a4b-it`; Gemini is
`google/gemini-3.1-flash-lite`, from the shared registry. Do not introduce Gemini
3.5 or change the registry based on conversational shorthand.
