**From build-plan:** feature V2.11a
**Build attempt:** 1

## Goal
Reuse compatible successful correction results from SQLite without another paid request. Approved explicitly in chat on 2026-10-22; user selected SQLite after technical clarification.

## In scope
- Exact submitted text, model, mode, prompt version and generation parameters identify compatible successes, including unchanged results. Newest generated matching success wins. No expiry while non-deleted history exists.
- Gemma searches all non-deleted matching history after validating supplied references. Gemini stays within the displayed Gemma history entry.
- Reuse original IDs and metrics without creating attempts; saved explanations stay reachable.
- Transactional lookup/touch; deleted parents cannot qualify. Storage failures prevent upstream calls. Lookup precedes upstream availability.
- Saved-result note and per-model Generate again action with New paid request text. Refresh bypasses reuse; old results remain during pending/failure. Gemma refresh resets pair on success, Gemini refresh replaces Gemini only.
- lastUsedAt updates on cache return or new attempt start. History sorting, filters and displayed Last used use it, preserving original timestamps.
- Optional forceRefresh input defaults false; required isCached success flag; lastUsedAt history contracts and database migration backfilled from createdAt.

## Out of scope
Redis, browser text storage, draft recovery, offline support, app-data caching, request coalescing. Separate simultaneous cache misses may create separate paid attempts. Existing explanation and exchange-rate reuse unchanged.
