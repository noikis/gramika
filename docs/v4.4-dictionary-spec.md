# V4.4: Russian dictionary definitions

Implementation handoff, 2026-11-01. This document records the planning session;
it does not claim that the application feature is implemented. Implement in a
later session. Do not overwrite another active Blueprint feature specification.

## Goal

Look up one selected Russian word from the correction workspace using the
self-hosted Wiktapi service. Resolve the selected form to dictionary headwords,
fetch their definitions, and display them in a Dictionary tab inside the same
drawer used by Translation. Dictionary lookup is separate from LLM Explain.

Definitions and examples must remain verbatim. No LLM call, abbreviation
expansion, text correction, paraphrase, contextual ranking, or generated example
is part of V4.4.

## Agreed behavior

- Add an explicit Dictionary action for selections in Original, clean Result,
  and the original/edited comparison surfaces that already support selection.
- Lookup requires one Russian word. Trim surrounding whitespace and punctuation;
  preserve internal hyphens, Cyrillic letters including ё, and combining acute
  stress marks. Reject phrases, empty selections, digits, and mixed-script text
  with localized guidance. Never silently take the first token or whole text.
- Capture selection before toolbar focus changes, supporting pointer and keyboard
  activation. Submit only the word, never the surrounding sentence or history.
- Open the shared language-tools drawer and activate Dictionary on a valid
  lookup. Translation actions activate Translation. Render only the active tab's
  panel. Both tab selectors may remain visible; their content must not appear
  simultaneously.
- Reuse the existing desktop sidebar and mobile sheet presentation, breakpoints,
  theme, and installed components. Do not add a separate dictionary screen or
  another modal layered over the translation drawer.
- Retain each tool's current result when switching tabs. Switching tabs must not
  trigger another request. Existing Translation persistence remains intact.
- Dictionary state is in memory only: no SQLite history or browser persistence.
  Clear it on New correction, local-data clearing, and reload. Closing/reopening
  the drawer retains it during the current workspace session.
- V4.4 lookup actions belong to the correction workspace. Extending dictionary
  actions into History, explanations, or translation output is not required.

## Dictionary service and lookup algorithm

Base URL: `https://dictionary.noikis.ru`. Documentation: `/_openapi.json` and
`/_scalar`. See [dictionary API reference](dictionary-api.md).

1. Frontend validates the selection and submits the normalized selected word to
   the application backend. Backend repeats validation independently.
2. Backend calls `GET /v1/ru/resolve/{word}?lang=ru`, encoding the path segment.
3. Validate the updated resolve response. Each match has `lemma`, nullable `pos`,
   `form`, `grammar`, `unmappedTags`, and `sources`. An optional upstream
   `references` field is ignored by the app adapter.
4. Group matches by the exact returned lemma, preserving first-seen order,
   capitalization, stress, and all grammatical alternatives. Do not choose the
   first lemma, require a nominative tag, or merge different headwords.
5. Fetch `GET /v1/ru/word/{lemma}/definitions?lang=ru` once per distinct lemma.
   Use the returned lemma directly; the dictionary service now strips Wiktionary
   section references from it. Do not follow references in gloss text recursively.
6. Adapt the validated definitions and their corresponding resolve matches to
   the shared application contract below.
7. Return all headword results in order. An empty resolve result returns
   `{ query, results: [] }`. Do not perform exact-word or search fallback.

A dictionary headword is not always singular nominative: verbs may resolve to
infinitives, participles to participle entries, and plural entries may have their
own meanings. Resolution describes possible analyses, not the analysis selected
by sentence context.

If a definition request returns 404, omit that headword and continue with other
headwords. If none have definitions, return an empty result. Any timeout, network
failure, malformed response, or other upstream error fails the lookup rather than
silently presenting partial results as complete.

## Shared application contract

Define public schemas in `packages/contracts`, export them through its existing
entry point, and infer TypeScript types from Zod. Backend and frontend use the
same schemas. The following notation describes their required shape:

```ts
export const DictionaryMatchSource = z.enum([
  'headword', 'inflection', 'form-of',
])
export const DictionaryExampleSource = z.enum([
  'wiktionary', 'generated',
])

type DictionaryResponse = {
  query: string
  results: DictionaryResult[]
}

type DictionaryResult = {
  word: string
  edition: string
  matches: DictionaryMatch[]
  definitions: DictionaryDefinition[]
}

type DictionaryMatch = {
  pos: string | null
  form: string
  grammar: DictionaryGrammar
  unmappedTags: string[]
  sources: DictionaryMatchSource[]
}

type DictionaryDefinition = {
  pos: string | null
  language: string
  senses: Array<{
    glosses: string[]
    tags: string[]
    examples: Array<{
      text: string
      source: DictionaryExampleSource
    }>
  }>
}
```

Declare the corresponding inferred types for both source enums. Reference values
through `.enum`, including `DictionaryExampleSource.enum.wiktionary`.
`generated` is reserved vocabulary only; nothing generates examples in V4.4.

Mirror the updated API's grammar schema. Each property is optional, arrays
contain enum values, and an empty object is valid:

| Field | Allowed values |
| --- | --- |
| cases | nominative, genitive, dative, accusative, instrumental, prepositional |
| numbers | singular, plural |
| genders | masculine, feminine, neuter |
| animacies | animate, inanimate |
| tenses | present, past, future |
| persons | first-person, second-person, third-person |
| moods | indicative, imperative, conditional, subjunctive |
| voices | active, passive |
| degrees | positive, comparative, superlative |
| aspects | perfective, imperfective |
| verbForms | infinitive, participle, adverbial |
| shortForm | literal true |
| stressed | literal true |

Use Zod enums for finite sets rather than duplicate TypeScript enums. Preserve
unspecified properties and alternatives; do not infer defaults. Keep `pos`,
definition-sense `tags`, and `unmappedTags` as strings because their upstream
vocabulary is not closed. Definition-sense tags are distinct from resolve grammar.

Adapter rules:

- Preserve headword, definition-entry, sense, gloss, and example order.
- Preserve separate entries even when they share the same part of speech.
- Keep each example attached to its original sense. Do not flatten or deduplicate
  senses or examples, or split glosses on punctuation.
- Retain text exactly, including abbreviations, spelling, spacing, and stress.
- Map examples to `{ text, source: 'wiktionary' }`. Strip `ref`,
  `bold_text_offsets`, and other unused upstream example fields.
- Strip raw URLs, HTTP metadata, and upstream `references` from app results.
- Accept empty arrays. Do not invent glosses or examples for sparse entries.
- Validate required fields; accept and ignore extra upstream object fields.
  Never cast malformed upstream JSON into the application contract.

## Backend interface and operational defaults

Use `POST /api/dictionary/lookup` with JSON `{ word: string }`. POST keeps the
selected word out of the application URL and follows the translation API pattern.
Return `DictionaryResponse` on HTTP 200, including the no-match case.

Use a shared Zod error-code enum and the existing error-envelope convention:

```ts
{ error: { code: DictionaryErrorCode } }
```

| Code | HTTP status | Meaning |
| --- | --- | --- |
| INVALID_INPUT | 400 | Selection is not one supported Russian word |
| DICTIONARY_UNAVAILABLE | 503 | Upstream reverse index unavailable |
| DICTIONARY_TIMEOUT | 504 | Lookup exceeded the timeout |
| DICTIONARY_FAILED | 502 | Network, other upstream HTTP, or schema failure |

Use a server-only `DICTIONARY_BASE_URL` setting, defaulting to the service URL.
Validate it as an HTTP(S) URL in the existing configuration layer. The client
cannot supply an upstream URL. Document the setting in `.env.example` and the
container guide, and pass it through Compose if configurable deployment requires
it. Use direct dictionary HTTP access, independently of the OpenRouter proxy.

Use native fetch or the repository's existing HTTP facilities with an injectable
transport for tests. Apply a 15-second overall lookup deadline, sequential
definition requests, no automatic retries, and no persistent cache. The deadline
is an implementation default; it covers resolve plus definition fetches.

Do not log words, request bodies, full upstream URLs, or raw responses. Render
dictionary strings as text, never HTML. Expose localized application errors rather
than upstream message bodies. No API key, LLM request, or database migration is
needed.

## Dictionary tab presentation

Show loading, ready, empty, and error states inside Dictionary. A new lookup
replaces the previous visible lookup; stale responses must never replace a newer
one. Use cancellation/request identity protection. Clearing the workspace cancels
or invalidates in-flight lookups. A retry repeats the same word explicitly.

For each headword show:

- Headword, and selected form when it differs.
- Separate definition groups, labeled with localized part-of-speech labels.
- All senses in source order with numbered, verbatim gloss text. Multiple glosses
  stay within their original numbered sense.
- Examples collapsed independently under each sense, with their count. Expanded
  examples display verbatim text and a localized Wiktionary source label. Omit
  the examples control when the array is empty.
- A recognized `participle` sense tag can supply the localized label Причастие.
  Avoid duplicate labels such as adv plus adverb. Other labels must remain tied
  to the entry/sense that supplies them; do not extract labels from gloss text.

Retain detailed `matches`, `grammar`, `unmappedTags`, and provenance in the
contract. A full morphology inspector is outside the initial card: do not present
one possible case as the case in the user's sentence. Unknown part-of-speech or
sense-label values must not prevent reading the definition.

If a sense has no glosses, retain the response data but omit a blank numbered
definition from the UI. If there are no readable glosses anywhere, show a
localized message that no definitions were found. Do not manufacture text from
tags or examples.

Provide accessible tab roles, keyboard navigation, labeled icon actions, loading
announcements, and errors. Reuse drawer focus/close behavior and return focus to
the initiating action when closed. Localize interface text in English, French,
and Russian; dictionary content remains Russian regardless of interface locale.

## Existing evidence and limitations

The inspection script is `scripts/dictionary-lookup.mjs`. It writes adapted
`<word>.json` and original `<word>.raw.json` files under the ignored
`test-results/dictionary/` directory. Its current adapted output does not yet
retain resolve matches; update it to the accepted contract when implementing the
shared adapter, preferably by reusing the same mapping rather than duplicating it.

Live verification on 2026-11-01 reran 95 saved words with 234 successful HTTP
responses. The API returned 208 resolve matches. Section references now resolve
to usable headwords: `мной` includes lemma `я` while retaining
`я#(местоимение)` only in upstream `references`.

These are observations, not comprehensive production verification. `детьми` and
`дочерьми` still returned no matches. Earlier probes also showed incomplete
coverage for `внемлет` and `обинякового`. No-match wording must not imply a word
is incorrect. Definitions can be terse references rather than useful standalone
explanations, and example coverage is uneven.

Do not fix or redesign the external dictionary service as part of V4.4. Its
structured resolve API is a prerequisite already observed live.
