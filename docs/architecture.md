# Архитектура

## Принятый подход

Один репозиторий, npm workspaces, три пакета: web, server, contracts. Один серверный процесс и SQLite. Не использовать pnpm, Lerna, Turborepo, микросервисы или очереди без новой конкретной необходимости.

Стек: React + Vite + TypeScript; shadcn/ui + Tailwind CSS; Node.js + Fastify + TypeScript; общие Zod-схемы; SQLite. HTTP-клиент OpenRouter — Undici с отдельной настройкой прокси.

Версии зависимостей, слой доступа к SQLite и точные настройки TypeScript ещё не выбраны. `strict: true` не утверждён пользователем.

```text

    app.ts                  # Создание приложения, регистрация плагинов
    server.ts               # Прослушивание порта и завершение процесса
    config.ts               # Проверка ENV
    plugins/
      database.ts           # Подключение БД и жизненный цикл
      openrouter.ts         # HTTP-клиент и жизненный цикл
    modules/
      correction/
        routes.ts
        service.ts
      history/
        routes.ts
        repository.ts
      models/
        routes.ts
    llm/
      client.ts
      prompts.ts
      models.ts
    db/
      schema.ts
      migrations/
packages/
  contracts/                # Zod-схемы и выведенные TypeScript-типы

```

Это план, а не описание существующего кода. Дополнительные файлы создавать по реальной необходимости.

## Границы и поток данных

React отправляет текст и выбранную модель в Fastify. Сервер проверяет запрос, формирует Strict-промпт, вызывает OpenRouter, сохраняет результат и метрики, возвращает результат клиенту. Клиент вычисляет diff и выполняет копирование.

- Web не обращается к OpenRouter напрямую и не знает API-ключ.
- Contracts содержит публичные схемы запросов и ответов; типы выводятся из Zod. Серверные зависимости и схема БД туда не входят.
- Сервис коррекции — обычный TypeScript-код, отделённый от HTTP и пригодный для оценочных прогонов.
- Репозиторий данных изолирует SQL от маршрутов.
- Внешние данные проверяются во время выполнения; TypeScript сам по себе не проверяет сетевые ответы.

Предполагаемые возможности API: выполнить коррекцию, получить историю и одну проверку, удалить запись истории, получить доступные модели. Точные пути, схемы ответов, пагинация и ошибки будут определены при подготовке контракта API; не считать их уже утверждёнными.

## Fastify

- Маршрутные модули — отдельные плагины, регистрируемые явно через register.
- Общие инфраструктурные плагины подключаются до маршрутов. fastify-plugin применяется там, где действительно нужен общий доступ к ресурсу.
- Локальные hooks и настройки маршрутов остаются инкапсулированными.
- app.ts создаёт приложение без открытия порта; server.ts запускает его.
- Соединение БД и HTTP-клиент освобождаются через жизненный цикл приложения.
- Обработчики маршрутов выполняют адаптацию HTTP, а не содержат всю бизнес-логику.
- Autoload не нужен для нескольких модулей.

Основа: [плагины Fastify](https://fastify.dev/docs/latest/Guides/Plugins-Guide/) и [инкапсуляция](https://fastify.dev/docs/latest/Reference/Encapsulation/).

## Предварительная модель данных

| Сущность | Назначение и предполагаемые данные |
| --- | --- |
| Проверка | Идентификатор, время, исходник, исправленный текст, язык, режим Strict |
| Запрос модели | Связь с проверкой, модель, версия промпта, статус, длительность, входные/выходные/reasoning-токены, фактическая стоимость при наличии |
| Настройки | Выбранная модель и необходимые пользовательские значения по умолчанию |

Это концептуальная схема, не готовая миграция. Нужно решить представление неудачных попыток, повторных запросов и результата из кеша. Не подменять отсутствующие метрики нулём. Diff можно восстановить по исходнику и результату; хранение объяснений ошибок не требуется.

## Разработка и размещение

Один корневой package-lock.json, установка через npm. Планируются корневые команды dev, build, typecheck и test; они пока не реализованы. В разработке Vite и Fastify работают отдельными процессами. Порядок сборки задаётся явно: contracts, затем приложения; npm workspaces не заменяет планировщик графа сборки.

План размещения: один контейнер, Fastify обслуживает API и собранный фронтенд, SQLite находится на постоянном томе. Подробности окружений — [environments.md](environments.md).

## Проверки архитектуры

API: Fastify inject, изолированная БД, заглушка LLM. Проверять общие контракты, сохранение/чтение истории, ошибки OpenRouter и прокси. UI: корректность diff, копирования и мобильного сценария. Оценки реальных моделей отделены от обычных тестов.
