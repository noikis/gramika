# Окружения и сеть

## Критическое требование

Обращения к OpenRouter должны проходить через VPN. Реализация различается между компьютером разработчика и Home Lab. Приложение не должно автоматически обходить настроенный серверный прокси при ошибке.

## Разработка на компьютере

VPN уже включён на уровне компьютера. Приложение использует обычное сетевое подключение без явно заданного прокси Home Lab. Не устанавливать адрес 10.201.0.2:8888 как значение по умолчанию для разработки.

Отсутствие явного прокси в приложении само по себе не доказывает прохождение через VPN. Ручная проверка пользователя описана ниже.

## Home Lab

Все серверные обращения к OpenRouter используют HTTP-прокси. Каталог доступных моделей задан локально в contracts; сетевой запрос каталога не выполняется:

```dotenv
OPENROUTER_PROXY_URL=http://10.201.0.2:8888
```

Пользователь предоставил пример проверки на Home Lab:

```sh
curl -4 -x http://10.201.0.2:8888 https://ifconfig.me
```

Команда здесь приведена как справочная и в рамках подготовки документации не выполнялась.

Для серверного окружения прокси обязателен. При отсутствии настройки запросы к OpenRouter блокируются ошибкой конфигурации. При недоступности прокси возвращается ошибка без прямого fallback. Конфигурация различает `GRAMOTA_ENV=development` и `GRAMOTA_ENV=homelab`. Для homelab допустим только настроенный обязательный адрес; неизвестное окружение блокирует коррекцию.

Undici-клиент OpenRouter получает отдельный ProxyAgent. Коррекция и ручной benchmark используют этот общий транспорт. Не создавать обходной сетевой путь во вспомогательном коде серверного окружения.

## Проверка VPN

- Проверить внешний IP через прокси и соответствие ожидаемому выходу VPN.
- При недоступном прокси убедиться, что приложение не обращается к OpenRouter напрямую.
- Отдельно проверить поведение самого прокси при падении VPN: он тоже должен блокировать прямой выход. Настройка приложения не гарантирует этого свойства инфраструктуры.

19 октября 2026 года пользователь сообщил, что при отключённом VPN доступ к OpenRouter запрещён. Считаем этот сценарий вручную проверенным пользователем. Точное окружение и трассировка проверки не записаны; это не новая проверка агента и не подтверждение готовности будущего контейнера. Публичный IP в документации не зафиксирован.

## Секреты и данные

- API-ключ OpenRouter: серверная переменная `OPENROUTER_API_KEY`.
- Не включать ключ в клиентскую сборку, git, логи или примеры конфигурации.
- `apps/server/.env.example` содержит имена и безопасные примеры, но не секреты. Сам `.env` приватный; агенты не должны его читать.
- Сейчас SQLite хранится локально: `apps/server/data/gramota.sqlite` по умолчанию или `SQLITE_PATH`. Постоянный том и сохранность при пересоздании контейнера предстоит проверить в пункте 6.
- Резервное копирование и восстановление базы предстоит определить; не считать Docker-том резервной копией.

## Размещение и доступ

План: один контейнер с Fastify, API и собранным React-приложением, отдельный постоянный том SQLite. Авторизация, домен, TLS и внешний доступ отложены по просьбе пользователя. Не выполнять публикацию приложения как часть настройки документации.

При проектировании доступа учесть, что браузерное копирование на телефоне требует подходящего безопасного контекста и поддержки Clipboard API; до определения TLS нельзя считать этот сценарий проверенным на сервере. В интерфейсе предусмотреть ручное копирование при отказе API.
